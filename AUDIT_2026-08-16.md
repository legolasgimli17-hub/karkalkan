# KârKalkan correctness audit — 2026-08-16

This review intentionally paused feature expansion and re-audited recent vNext work for financial correctness, access control, scaling behavior and seller-facing semantics.

## Material findings addressed

- Removed broad browser write/TRUNCATE/TRIGGER privileges from synchronization artifact tables and retained authenticated read-only access.
- Added missing composite ownership-FK indexes for live-signal and operating-expense tables.
- Replaced local-only webhook `active` trust with provider-side Trendyol webhook reconciliation; repair/rotation updates or activates the provider subscription.
- Unified dashboard/risk/portfolio cash vocabulary so stoppage is not omitted from one view while included in another.
- Added explicit pagination and `DATA_TOO_LARGE` guards to large financial reads rather than allowing first-page truncation to look like a complete total.
- Renamed the prior store-health concept to Financial Data Confidence; non-applicable evidence is excluded rather than awarded artificial 0/100 scores.
- Made sales evidence volume-weighted instead of product-row-count-weighted.
- Made portfolio operating contribution unknown until product-cost coverage is complete; missing product cost is never treated as zero.
- Fixed frontend null handling so an unknown contribution cannot render as zero currency.
- Removed the operating-expense ledger's silent 200-row limit and replaced it with an explicit review ceiling/error.
- Expanded CI to run finance-semantic tests and syntax-check all vNext browser JavaScript.

## Validation boundary

These controls can be verified with repository CI, Supabase schema/advisors and endpoint authentication behavior. Actual Trendyol webhook delivery and full order → claim → settlement → cargo reconciliation still require a real seller account and remain a separate end-to-end validation item.
